# 잔월 호텔 — 첫 보관함 이후 시각 연출 후속 작업

작성 기준: 2026-10-03. 이 문서는 **아직 구현하지 않은 후속 작업의 계획과 완료 기준**이다. 아래 체크리스트는 실제 구현과 검증을 마친 뒤에만 완료로 바꾼다.

## 1. 현재 어디까지 됐는가

**새로운 스토리 연출은 도착 대화(`arrival`)와 첫 열쇠 보관함 조사(`keys`)까지다. 그 뒤 18개 노드는 플레이할 수 있지만, 이번에 만든 확대 조사·발견·인물 반응 흐름으로 개편되지는 않았다. 첫 번째 사건 전체를 완성한 상태도 아니다.**

공통 퍼즐 화면 개편은 이미 12개 스테이지에 적용됐다. 따라서 다음 작업의 중심은 보드를 다시 만드는 것이 아니라, 퍼즐 앞뒤의 조사와 이야기 전달을 이어 붙이는 것이다.

| 구분 | 현재 구현 | 남은 작업 |
| --- | --- | --- |
| 첫 진입 | 짧아진 도착 대화, 서윤·하린 추가 포즈 | 이후 대화에도 상황에 맞는 시선·포즈·행동 적용 |
| 첫 보관함 | 보관함 확대 → 퍼즐 → 흰 실 발견 카드 → 인물 반응 | 이 흐름을 다른 조사 대상에도 적용할 수 있도록 일반화 |
| 퍼즐 공통 | 큰 보드, 목표 그림/잔여 수, 묶음 미리보기, 특수 블록과 장애물 표현, 제거·생성·낙하 연출 | 사건별 조사 목적과 결과 연결, 효과 가독성·속도 조정 |
| 탐색 | 주요 진행 버튼, 로비 벨·시계 조사, 보관함 완료 표시 | 장소별 조사 대상, 조사 전후 그림 변화와 상태 유지 |
| 수첩 | 기존 단서 8개 + 흰 실 관찰 1개, 그림 표시 기능 | 각 단서 전용 그림, 앞뒤 보기, 발견 화면과 일관된 정보 |
| 추가 그림 | 보관함, 서윤·하린 포즈 4개, 흰 실·열쇠·수건 | 인계표·바구니·달 태그·전화·기록·사진·편지·결말 장면 |
| 검증 | 기존 기록상 EditMode 115개, 전체 진행, 효과 8종, 첫 조사 녹화 검증 | 후속 구간 실제 플레이·저장·화면 검증 |

`basket` 단서에 열쇠 그림을 연결한 것은 완료돼 있다. 하지만 바구니 확대 조사나 열쇠를 꺼내는 장면이 구현된 것은 아니다. 로비의 완료 표시도 배경 전체가 바뀌는 기능은 아니다.

현재 구현과 검증 기록: [VisualInvestigation.md](VisualInvestigation.md). 기존 구조: [HotelPrototype.md](HotelPrototype.md), [PCStagePresentation.md](PCStagePresentation.md).

## 2. 이번 후속 작업의 목표

플레이어가 설명을 읽기 전에 **무엇을 조사하는지, 무엇이 달라졌는지, 왜 다음 장소로 가는지** 화면에서 알 수 있게 한다.

기본 흐름은 다음과 같다. 모든 노드에 블록 퍼즐을 새로 넣는다는 뜻은 아니다. 기존 대화·퍼즐·수수께끼 종류를 유지하면서 필요한 연출을 붙인다.

> 장소에서 대상 발견 → 대상 확대·간단한 조작 → 기존 퍼즐/추리 → 물건 또는 공간의 변화 → 짧은 인물 반응 → 수첩과 다음 목적지 갱신

- 2D 배경과 인물을 유지한다. 첫 후속 작업에 자유 이동이나 3D 전환을 포함하지 않는다.
- 앞의 스토리 참고 영상에서는 대상 확대, 인물 반응, 발견 장면으로 주의를 유도하는 방식을 가져온다.
- 세 번째 퍼즐 참고 영상에서는 목표와 보드의 위계, 특수 효과 구분, 성공 후 변화가 보이는 방식을 가져온다.
- 그림에서 이미 전달된 사실을 대사로 다시 길게 설명하지 않는다. 일반 반응은 1~3개의 짧은 발화를 우선하되 필요한 인과관계를 생략하지 않는다.
- 읽어야 하는 기록에는 확대와 재열람을 제공한다. 텍스트를 줄인다는 이유로 단서의 시간·방향·약속 내용을 지우지 않는다.
- 장식용 클릭만 늘리지 않는다. 뒤집기·꺼내기·대조하기처럼 실제로 정보를 드러내는 조작을 우선한다.

### 유지할 이야기와 장소

사라진 303호 열쇠를 따라가다 달 모양 태그를 발견하고, 빈 객실의 전화가 자동 시험 신호임을 알아낸 뒤, 잊힌 공동 서재와 다시 열겠다는 약속을 되찾는 이야기다. 새 범인이나 초자연적 반전을 추가하는 작업은 아니다.

기존 장소는 **로비(`lobby`) → 3층 복도(`corridor`) → 기록 보관실(`archive`)** 세 곳이다. 세탁실은 현재 존재하는 장소가 아니다. 세탁물의 이동은 로비의 인계 기록과 복도의 바구니로 보여준다. `ending`의 데이터상 장소는 로비다. 달의 방은 우선 결말 전용 삽화로 보여주고, 네 번째 탐색 장소를 추가하려면 별도 범위로 다룬다.

## 3. 구현 순서

### P0. 다른 대상에도 쓸 수 있는 조사 화면으로 정리

현재 `ShowInspection`은 보관함 그림, 303호 제목, 수건 설명, “하린에게 보여 주기” 버튼을 직접 사용한다. 다른 노드에 `inspection`만 지정하면 그 노드의 조사 장면이 완성되는 구조가 아니다.

- [ ] 노드별 확대 그림, 제목, 짧은 설명, 발견 그림, 다음 행동 문구를 데이터로 지정할 수 있게 한다.
- [ ] 그림 ID를 등록된 Sprite로 연결하는 조회 구조를 만들고, 보관함·흰 실 전용 분기를 늘리는 방식은 피한다.
- [ ] 조사 전과 발견 후의 표시를 구분한다. 정보가 없는 기존 노드/MOD는 기존 화면으로 정상 진행한다.
- [ ] 발견 화면과 수첩이 같은 단서 그림 및 MOD 우선순위를 사용하게 한다.
- [ ] 이미 보상으로 지급하는 단서는 발견 연출에서도 같은 ID를 참조한다. 화면을 추가할 때마다 수첩 항목을 복제하지 않는다.
- [ ] 새 필드는 선택 항목으로 추가하고 유효성 검사를 마련한다. 아래 설계 항목을 이미 존재하는 JSON 필드로 간주하지 않는다.

최소 설계 항목: 확대 배경 ID, 조사 제목/설명, 발견할 기존 단서 ID 또는 별도 관찰 ID, 조사 전후 그림 ID, 버튼 문구. 구체적인 필드명은 구현 시 결정한다. 범용 연출 엔진을 먼저 크게 만드는 대신 `keys`와 `register` 두 대상이 같은 흐름을 사용할 만큼부터 정리한다.

**P0 완료 기준:** 기존 보관함을 유지하면서 인계표 조사에 보관함 그림이나 하린 전용 문구가 새어 나오지 않는다. 선택 필드가 없는 콘텐츠도 열린다.

### P1. 첫 사건을 끝까지 연결 — 가장 먼저 만들 구간

`register`부터 `key_return`까지 완성한다. 열쇠를 찾았다는 설명을 듣는 데서 끝내지 않고, 이동 흔적을 보고 바구니를 찾아 열쇠를 돌려주는 과정이 화면에 남게 한다.

| 순서 / 노드 | 현재 역할 | 추가할 화면·조작 | 완료 기준 |
| --- | --- | --- | --- |
| 3. `register` | 로비, `stage_02`, `handover` 획득 | 인계대/인계표 확대. 퍼즐 후 17:00 수건 인계·17:10 파란 바구니 이동·17:20 빈 카트 복귀를 그림과 시각으로 드러냄 | 기록 세 항목을 확대·재열람할 수 있고, 다음 추리에 필요한 이동 정보가 보임 |
| 4. `route_riddle` | 로비, 순서형 `route` | 수건·바구니·빈 카트 그림 카드를 순서대로 선택. 선택한 순서를 화면에 표시 | 기존 정답 판정을 유지하며 문장 전체를 다시 읽지 않아도 카드를 구분함 |
| 5. `keeper` | 복도, 도식 대화 | 도식이 바구니 쪽을 바라보거나 가리키는 포즈. 조사 대상에 짧은 강조 | 대화 종료 후 어디를 눌러야 하는지 보임 |
| 6. `basket_search` | 복도, `stage_03`, `basket` 획득 | 파란 바구니 확대 → 퍼즐 → 천 사이의 303호 열쇠를 드러내고 꺼냄 | 열쇠가 나온 위치를 확인할 수 있고, 기존 `basket` 보상을 한 번만 지급 |
| 7. `tag_search` | 복도, `stage_04`, `moon_tag` 획득 | 바구니 바닥 확대 → 퍼즐 → 달 태그 발견. 앞면 달 표식과 뒷면 문구를 뒤집어 확인 | 객실 번호가 없다는 점과 “사람을 기다리는 방”이라는 단서가 보임 |
| 8. `key_return` | 로비, 열쇠 반환 대화 | 열쇠를 건네는 짧은 장면, 하린의 안도, 보관함 열쇠 자리 변화 | 첫 사건이 끝났다는 변화와 달 태그의 미해결 의문을 함께 전달 |

- [ ] 위 여섯 노드의 새 연출을 구현한다.
- [ ] 인계표, 바구니 조사 전후, 303호 열쇠 발견 장면, 달 태그 앞뒤, 도식의 안내 포즈를 준비한다.
- [ ] 수첩에서 인계표·열쇠 흔적·태그를 다시 확인할 수 있게 한다.
- [ ] 조사 완료에 따른 보관함/바구니 상태가 장소 재방문과 저장 복원 후에도 맞게 보인다.
- [ ] 도착부터 열쇠 반환까지 실제 플레이를 녹화하고, 다음 목적지를 대사 없이도 짚을 수 있는지 검토한다.

**P1 완료 기준:** 첫 사건 전체가 “대화 → 보드 → 보상 설명”의 반복에서 벗어나, 인계표 확인 → 복도 바구니 추적 → 열쇠/태그 발견 → 반환의 시각적 흐름으로 이어진다. 이 단계가 끝나기 전에는 후반부 아트를 대량 제작하지 않는다.

- [ ] 실제 시각 18시까지 기다리는 조건을 만들지 않는다. 이야기 속 시각을 재현하는 장면으로 처리한다.

**P2 완료 기준:** 전화의 원인을 긴 해설로 처음 알려주지 않는다. 이미 본 시간·신호 방향·수화기 반응을 플레이어가 연결할 수 있다.

- [ ] 문 선생의 회상/반응 포즈를 추가한다. 현재 인물 표시 구조의 제약을 확인하고, 여러 인물이 필요하면 장면을 나눠 연출한다.
- [ ] `last_boxes`는 데이터상 기록 보관실이다. 배경과 설명이 별도 서재에 이미 도착한 것처럼 충돌하지 않도록 맞춘다.
- [ ] 결말 전용 삽화를 새 탐색 장소로 오인하지 않게 한다. 새 장소를 추가하는 경우 장소 UI·검증·저장을 함께 확장한다.
- [ ] 전체 20개 노드를 새 게임부터 엔딩까지 실제로 진행해 연결을 검토한다.

**P3 완료 기준:** 사라진 열쇠에서 시작한 조사가 달 태그, 전화 메모, 옛 기록을 거쳐 서재의 재개장으로 이어진다는 인과관계가 화면에 남는다.

## 4. 구간별 구현과 함께 마무리할 공통 항목

- [ ] **수수께끼 4개:** `route`, `phone`, `room`, `timeline`에 필요한 그림을 제공한다. 기존 `choice`/`order` 판정을 우선 재사용한다. 드래그가 필수는 아니며 클릭으로 순서를 선택할 수 있다.
- [ ] **그림 수첩:** 8개 기존 단서의 정보와 그림을 연결한다. 태그·사진처럼 앞뒤 정보가 있는 항목은 다시 볼 수 있다.
- [ ] **장소의 변화:** 완료 표시뿐 아니라 물건 유무·정리 상태·조명 등 필요한 변화가 보인다. 가능한 상태는 기존 완료 노드에서 계산한다.
- [ ] **탐색 대상:** 선택 조사와 필수 진행을 구분해 배치한다. 현재의 로비 벨/시계 전용 코드만 복제해서 모든 장소를 만들지 않는다.
- [ ] **대화:** 말하는 인물, 시선, 핵심 물건이 일치한다. 등장인물 수에 맞춰 무조건 UI 슬롯을 늘리기보다 필요한 장면부터 구성한다.
- [ ] **퍼즐 맥락:** 옆의 장면/목표 설명이 실제 조사 대상과 일치한다. 성공 후에는 해당 대상의 발견/변화로 돌아간다.
- [ ] **발견과 보상:** 일반 성공 창, 발견 카드, 단서 획득 알림이 같은 정보를 반복하지 않도록 연결한다. 퍼즐 결과와 실제 보상 지급은 계속 확인 가능해야 한다.
- [ ] **도움말:** 첫 등장 기능을 짧게 안내하고 다시 열 수 있게 한다. 일반 대화에 퍼즐 조작 설명을 반복해서 넣지 않는다.
- [ ] **마지막 연출 조정:** 확대/전환/발견 속도, 효과 대비, 클릭 잠금 시간을 실제 플레이로 조정한다. 풀 보이스·립싱크·걷기 애니메이션은 이번 필수 범위에 넣지 않는다.

## 5. 구현 시 지켜야 할 제약

### 저장과 수첩

- 기존 노드 ID, 선행 조건, 보상 ID를 우선 유지한다. 저장 검증이 완료 노드와 지급 단서의 일치를 확인하므로 기존 노드에 보상을 뒤늦게 추가하면 구버전 저장에 영향을 줄 수 있다.
- 흰 실은 `keys` 완료로부터 계산하는 관찰 기록이며 저장 파일에 새 보상으로 넣지 않았다. 후속 발견도 기존 보상 단서와 별도 관찰을 구분한다.
- 현재 수첩은 **기존 단서 8개 + 관찰 1개 = 9개**, 최대 12개다. 모든 노드에 `discovery`를 추가하면 수용량 검증에 걸릴 수 있다. 먼저 중복 항목을 방지하고, 필요할 때 수첩 페이지/슬롯과 검증을 함께 확장한다.
- 발견 화면을 보여줬다고 완료 저장을 앞당기지 않는다. 현재 진행 중 퍼즐/대화는 재개 시 해당 조사부터 다시 시작하는 방식이다. 저장 시점을 바꾸려면 중간 상태 복원과 보상 중복 방지를 함께 설계한다.
- 완료한 노드의 그림 변화는 재방문과 저장 복원 후에도 같은 결과여야 한다.

### 씬, 콘텐츠 원본, MOD

- UI는 기존 원칙대로 Unity 씬에서 저작한다. 런타임에 새 Canvas/Button/Text를 생성하는 방식으로 우회하지 않는다.
- `HotelSceneBuilder.UpgradeInvestigation`은 이미 적용된 씬에서 반환하는 1회 마이그레이션이다. 재실행만으로 후속 UI가 추가된다고 가정하지 않는다. 기존 씬의 수동 편집을 보존하는 명시적인 추가 저작/마이그레이션을 사용한다.
- `base.json` 수정과 저작 스크립트 결과가 서로 달라지지 않게 한다. `Tools/author_hotel_content.py`는 기본 콘텐츠와 샘플 MOD를 다시 쓰므로 무심코 전체 실행하지 않는다.
- 현재 `Pose`와 `Evidence`는 제한된 ID를 직접 분기한다. 후속 에셋은 등록 기반으로 확장하고, 알 수 없는 포즈/그림에는 기본 표현을 제공한다.
- 현재 수첩은 MOD 단서 이미지를 우선하지만 발견 화면은 내장 `Evidence`를 직접 사용한다. 두 화면의 조회 순서를 통일한다.
- 새 그림을 제공하지 않는 기존 MOD도 진행 가능해야 한다. 선택 필드 누락 때문에 기존 콘텐츠를 거부하지 않는다.
- 기존 퍼즐 Domain과 이미 구현된 공통 턴 연출을 유지한다. 연출 추가를 위해 퍼즐을 강제 승리시키거나 결과 데이터를 따로 조작하지 않는다.

## 7. 완료 판정과 검증 기록

다음 기준은 후속 구현을 완료했다고 보고하기 위한 조건이다. 문서 작성 자체가 아래 항목의 완료를 뜻하지 않는다.

- [ ] 수정 범위에 맞는 EditMode 테스트와 콘텐츠 검증이 통과한다. 기존 115개 통과는 이전 구현의 기준 기록이다.
- [ ] 해당 구간을 실제 UI 입력으로 진행한다. 그림만 배치한 화면이나 강제 완료 상태로 플레이 가능 여부를 대신하지 않는다.
- [ ] 기존 전체 진행 자동 검증을 실행해 20개 노드, 12개 퍼즐, 4개 수수께끼가 끝까지 연결되는지 확인한다.
- [ ] 실패·재도전·탐색 복귀·수첩 열기/닫기 후에도 진행이 막히지 않는다.
- [ ] 첫 보관함 완료 저장, 사건 중간 저장, 엔딩 완료 저장을 복원한다. 단서가 중복되거나 누락되지 않는다.
- [ ] 새 필드/그림이 없는 MOD와 그림을 교체한 MOD에서 진행과 기본 이미지 복귀를 확인한다.
- [ ] 1600×900과 1280×720에서 대사, 발견 카드, 수첩, 목표와 버튼이 겹치거나 잘리지 않는다.
- [ ] 공통 퍼즐 코드를 수정했다면 기존 8종 효과 검증도 다시 실행한다. 효과 검증만으로 새 스토리가 검증됐다고 보고하지 않는다.
- [ ] 실제 플레이 영상으로 대상 확대 → 조작 → 결과 → 인물 반응의 연결을 검토한다. 첫 구간만 촬영한 영상을 전체 캠페인 영상으로 표시하지 않는다.
- [ ] 새로 제작한 그림의 원본·Sprite·씬 참조를 함께 보존하고 생성/편집 내역을 기록한다.
- [ ] 구현한 노드, 남은 노드, 검증 해상도와 결과를 구분해 완료 보고한다.

기존 실행/검증 명령은 [VisualInvestigation.md](VisualInvestigation.md)를 따른다. `Builds/Hotel/FirstInvestigation/MoonlitHotel-FullPlay.mp4`는 이름과 달리 **첫 보관함 구간만 담은 기존 영상**이다. `Builds`의 실행 파일·로그·영상은 새 체크아웃에 없을 수 있으므로 필요하면 다시 생성한다.

## 8. 바로 다음에 시작할 작업

**P0 일반화와 `register` 한 구간을 먼저 함께 구현한다.** 인계표 확대 → 기존 `stage_02` → 시각화된 인계 기록 → 수첩 저장까지 직접 플레이한다. 그 구조로 `route_riddle`, `keeper`, `basket_search`, `tag_search`, `key_return`을 연결해 첫 사건을 완성한 뒤 P2, P3 순서로 확장한다.

다음 구현 요청에 사용할 지시문:

> 이 문서의 P0와 P1부터 진행한다. 기존 첫 보관함 연출과 공통 퍼즐 개선을 보존하고, 먼저 `register`의 인계표 조사 장면을 실제 플레이 가능하게 만든다. 이후 첫 사건의 열쇠 반환까지 연결한다. 현재 저장과 MOD 호환성, 씬 저작 원칙을 유지한다. 완료한 범위만 검증하고 보고하며, 이후 사건까지 구현된 것처럼 표시하지 않는다.
